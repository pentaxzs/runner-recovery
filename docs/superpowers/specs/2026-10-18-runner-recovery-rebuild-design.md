# 러닝 회복 트래커 재설계

작성일: 2026-10-18
상태: 검토 대기

## 1. 목표

**장경인대 증후군(ITBS)을 낫게 하는 것.** 대회 마감일은 없다.

기존 앱은 2026-05-24 마라톤을 향한 8주 카운트다운 구조로 만들어졌고, 대회가 지난 뒤
방치됐다. 목표가 "완주"에서 "회복"으로 바뀌었으므로 날짜 기반 고정 플랜을 버리고
**상태 기반 진행**으로 전환한다.

두 번째 목표는 **계속 쓰게 만드는 것**이다. 기존 앱은 배포까지 돼 있었는데도
(runner-recovery.netlify.app) 잊혔다. 기능 부족이 아니라 구조의 문제로 본다.

## 2. 사용자 상황

### 부상 상태
- 장경인대 증후군. **걷기는 무증상, 러닝 중 특정 거리에서 통증** (복귀 프로그램 단계)
- 마지막 러닝 시점과 통증 발생 거리는 미확인 → 앱 첫 실행 시 입력받는다

### 생활 일정
| 시간 | 내용 |
|---|---|
| 주중 | 07:30 출발 ~ 20:00–21:00 귀가 |
| 토요일 | 완전 휴식 |
| 일요일 | 10:00 영어 수업, 21:00 일어 수업 (오후가 통째로 비어 있음) |
| 골프 | 주 2회 × 30분 (연습장) |
| 출퇴근 | 지하철 왕복 120분, 걷기 왕복 30분 |
| 점심 | 날씨 좋으면 15분 걷기 |

### 여기서 나오는 설계 제약
- **평일 밤에 할 수 있는 건 5분이 한계다.** 9시 귀가 기준.
- **일요일 오후가 유일하게 긴 시간이다.** 메인 러닝 세션은 여기.
- **토요일은 비운다.** 휴식도 프로그램의 일부임을 화면이 말해야 한다.
- **하루 2.5시간이 지하철과 걷기에 쓰인다.** 이미 하고 있는 활동이므로 앱이 세어줘야 한다.

## 3. 기존 앱의 문제 (재설계 근거)

1. **매번 `0/7`로 열린다.** 모든 실행이 "아직 아무것도 안 했다"로 시작한다.
2. **3일째와 30일째가 똑같이 생겼다.** 정적 HTML이라 새로 볼 게 없다.
3. **쌓인 게 안 보인다.** 매일 리셋, 연속 기록 없음, 로그 14개 제한, 이번 주만 조회 가능.
4. **통증 추이 그래프가 없다.** 통증 점수와 시작 거리를 매일 입력받으면서 추세를 안 보여준다.
   회복 앱에서 가장 중요한 보상이 빠져 있다.
5. **평일 밤 체크박스 7개는 과하다.** 피곤한 날 7개를 보면 앱을 끈다.
6. **홈 화면에 없다.** PWA 요소가 전무해 Safari 주소창 뒤에 숨어 있다. 눈에 안 띄면 잊힌다.
7. **스케줄이 실생활과 안 맞는다.** 토요일=골프로 가정하는데 실제로는 휴식일이다.
8. **체크 상태가 DOM 인덱스 기반이다** (`{"2026-10-17__3": true}`). 운동을 추가하거나
   순서를 바꾸면 과거 기록이 다른 운동을 가리킨다. 확정적인 버그.
9. **Tailwind를 CDN에서 런타임에 받는다.** 오프라인에서 스타일 없이 뜨고, 매번 깜빡인다.

## 5. 정보 구조

### 탭 3개

- **오늘** (기본) — 매일 보는 유일한 화면
- **기록** — 통증 추이 그래프 + 세션 이력
- **가이드** — 운동 사전 (필수/권장/회복/자투리 필터)

설정은 모달로 유지.

### "오늘" 화면 — 위에서부터

순서가 핵심이다. **긍정으로 연다.**

```
┌──────────────────────────────┐
│ 🔥 12일째    오늘 9,240보     │  1. 이미 해낸 것
├──────────────────────────────┤
│  오늘의 한 가지               │  2. 큰 카드 하나
│  클램셸 + 힙 브리지   5분     │
├──────────────────────────────┤
│  ☐ 클램셸        15회 × 3    │  3. 필수 2개 = 연속 기록 기준
│  ☐ 힙 브리지     15회 × 2    │
├──────────────────────────────┤
│  자투리 (오늘의 3개)          │  4. 매일 바뀜
│  · 지하철: 한 발 체중 3정거장 │
│  · 데스크: 90분마다 일어서기  │
│  · 점심: 보폭 줄이고 걷기     │
├──────────────────────────────┤
│  ▸ 여유 있으면 (+10분)        │  5. 접힘
│  ▸ 뻐근하면 (회복)            │
├──────────────────────────────┤
│  [오늘 러닝 기록하기]         │  6. 러닝한 날만 노출
└──────────────────────────────┘
```

**평일 밤 기본 노출 체크박스는 2개.** 통증 입력은 러닝한 날만 뜬다 — 안 뛴 날에 물으면
그것도 미완료로 쌓인다.

요일별 "오늘의 한 가지":
- 월–금: 필수 2개 (5분). 러닝 지정일이면 해당 레벨 세션이 "한 가지"가 된다
- 토: **"오늘은 쉬는 날입니다"** — 필수 2개는 접힌 채로 두되 원하면 펼쳐서 할 수 있다.
  streak 계산에서는 중립 (9장)
- 일: 메인 러닝 세션 (오후 권장)

**러닝 지정일 결정**: 일요일은 항상 메인 세션. 주중 러닝일은 `settings.runDays`에
사용자가 고른 요일을 저장한다 (기본값 화·목). 연속 이틀이 되는 조합은 저장 시 막는다.

## 6. 데이터 모델

localStorage 키 prefix: `rr_v3_`. 기존 `runner_tracker_*_v2`는 읽지 않는다.

```js
// 운동 정의 — data.js 상수 (저장 안 함)
tasks: [{
  id: 'clamshell',
  title: '클램셸',
  tier: 'essential' | 'recommended' | 'recovery' | 'micro',
  contexts: ['home'],        // home | subway | desk | lunch | outdoor
  desc, detail, youtube
}]

// 체크 기록 — id 기반 (인덱스 아님)
checks: { "2026-10-18": ["clamshell", "bridge"] }

// 세션 기록 — 그래프의 소스. 개수 제한 없음
sessions: [{
  date: "2026-10-18",
  type: 'run' | 'walk' | 'golf',
  level,                     // run일 때 사다리 레벨
  distanceKm,
  hadPain: bool,
  painOnsetKm,               // 통증 있었을 때만
  painScore,                 // 0–10
  memo
}]

// 걸음 수 — 날짜별 덮어쓰기
steps: { "2026-10-18": 9240 }

settings: {
  painOnsetKm,               // 최초 입력값, 이후 세션마다 갱신
  runLevel,                  // 사다리 현재 칸
  runDays: [2, 4],           // 주중 러닝 요일 (0=일 … 6=토). 일요일은 항상 포함
  startedAt
}
```

### 파생값: `painFreeKm`

그래프와 진행 판단의 기준 지표다. 세션 하나에서 다음과 같이 계산한다.

```
painFreeKm = hadPain ? painOnsetKm : distanceKm
```

통증이 없었다면 "그날 뛴 거리까지는 괜찮았다"는 뜻이므로 **하한값**으로 쓴다.
`painOnsetKm`만 기록하면 통증이 없는 날 — 즉 가장 잘 풀린 날 — 그래프에 구멍이 뚫린다.

- **연속 기록은 저장하지 않고** `checks`에서 계산한다. 저장하면 어긋난다.
- 로그 개수 제한 없음. localStorage 5MB면 수년치가 들어간다.
- 날짜는 전부 **로컬 시간 기준** `YYYY-MM-DD`. `toISOString()` 금지
  (기존 코드 `index.html:344`에 UTC 잔재가 남아 있었다).

## 7. 진행 로직

**"오늘 뭘 할지 정하는 사다리"와 "나아지는지 보여주는 지표"를 분리한다.**

### 사다리 (`runLevel`)

걷기-뛰기 인터벌로 시작해 **뛰는 구간을 먼저 늘린다.** 총 거리는 그 다음.

```
Lv1  뛰기 3분 / 걷기 2분 × 4세트   (~2.0km)
Lv2  뛰기 3분 / 걷기 2분 × 5세트   (~2.4km)
Lv3  뛰기 4분 / 걷기 2분 × 5세트   (~2.9km)
Lv4  뛰기 5분 / 걷기 2분 × 5세트   (~3.4km)
Lv5  뛰기 6분 / 걷기 2분 × 5세트   (~3.9km)
Lv6  뛰기 8분 / 걷기 2분 × 4세트   (~4.2km)
Lv7  뛰기 10분 / 걷기 2분 × 3세트  (~4.5km)
Lv8+ 연속 러닝으로 전환, 이후 거리 +10%씩
```

사다리 정의는 `data.js`에 둬서 조정하기 쉽게 한다.

### 승급 / 강등

- 통증 없이 2회 연속 완주 → **+1 레벨**
- 통증 발생 → **−1 레벨**, `settings.painOnsetKm`을 그 값으로 갱신
- 통증 3회 연속 → **러닝 2주 중단 제안**, 걷기 + 강화만 하는 모드

날짜가 아니라 상태가 올린다. 2주를 같은 레벨에 머물러도 정상이다.

### 러닝 빈도

주 2–3회, **연속 이틀 금지.** 기본 배치: 일요일 오후(메인) + 주중 1–2회.
골프 연습과 같은 날 러닝이 잡히면 경고를 띄운다 — 한 발 버티기 안정성이 떨어진 상태에서
뛰면 폼이 무너진다.

### 매 러닝 카드에 고정 표시할 규칙

> 평지만 · 내리막 피하기 · 보폭 줄이고 걸음 자주(케이던스 +5~10%) · 통증 2/10 넘으면 즉시 종료

## 8. 자투리 미션

상황 태그가 붙은 미션 18–20개 풀. **날짜를 시드로 매일 3개**를 뽑는다
(같은 날 여러 번 열면 같은 3개, 다음 날 바뀜). 요일로 먼저 거른다 —
주말에 지하철·데스크 미션은 의미가 없다.

- 평일: `subway`, `desk`, `lunch`, `home`
- 주말: `home`, `outdoor`

초기 풀:

| 상황 | 미션 |
|---|---|
| 지하철 | 한 발에 체중 싣고 3정거장 (번갈아) |
| 지하철 | 손잡이 잡고 뒤꿈치 들기 20회 |
| 지하철 | 앉으면 다리 꼬지 않기 |
| 지하철 | 엉덩이 조이기 10초 × 10 |
| 지하철 | 계단은 올라갈 때만, 내려갈 땐 에스컬레이터 |
| 데스크 | 90분마다 일어서기 |
| 데스크 | 모션데스크 30분 서서 일하기 |
| 데스크 | 테니스공 발바닥 굴리기 2분 |
| 데스크 | 책상 옆 런지로 고관절 앞쪽 30초 |
| 데스크 | 무릎 사이 쿠션 끼고 조이기 15회 |
| 점심 | 15분 걷기 — 보폭 줄이고 걸음 수 늘리기 |
| 점심 | 경사 없는 평지 코스로 |
| 집 | 양치하면서 한 발 서기 30초씩 |
| 집 | 폼롤러 종아리 1분 |

"계단은 올라갈 때만"의 근거: 장경인대 통증은 무릎이 30도 부근으로 굽을 때 발생하는데,
내려가는 계단이 정확히 그 각도다. 올라가는 동작은 안전하다.

## 9. 연속 기록 (streak)

- 기준: **그날 필수 2개를 모두 체크**
- **토요일은 중립** — 해도 +1, 안 해도 끊기지 않음 (완전 휴식일이므로)
- **미완료 1일까지는 봐준다.** 정확히는: 오늘부터 거슬러 올라가며 세되,
  **최근 7일 구간 안에서 미완료가 1일까지면 끊지 않는다** (그날은 증가도 안 함).
  같은 7일 안에 두 번째 미완료가 나오면 거기서 멈춘다. 토요일은 세지 않고 건너뛴다.
  엄격한 streak는 한 번 깨지면 영영 안 돌아온다.

## 10. 일요일 밤 주간 리포트

일어 수업이 21시에 끝나므로 **일요일 22시 이후에만** 나타난다.
특정 요일 특정 시간에 앱을 열 이유를 만드는 것이 목적이다.

- 이번 주 필수 달성 N/7, 러닝 N회, 총 거리
- 통증: 지난주 대비 시작 거리 ↑/↓, 점수 평균
- 걸음 수 일평균
- **다음 주 제안** — 레벨 올릴지 유지할지, 근거와 함께

## 11. 걸음 수 연동

**웹 앱은 HealthKit을 직접 읽을 수 없다.** HealthKit은 네이티브 iOS API이고
Safari에 이를 노출하는 웹 API가 없다. 홈 화면에 설치한 PWA도 마찬가지다.

### 방식: iOS 단축어 → URL 파라미터

```
[단축어]
1. 건강 샘플 가져오기  (걸음 수 / 오늘 / 합계)
2. URL 열기
   https://runner-recovery.vercel.app/?steps=9240&date=2026-10-18
```

**홈 화면에 단축어 아이콘을 둔다.** 누르면 걸음 수를 읽어 앱이 그 값과 함께 열린다.
시간 기반 자동화는 쓰지 않는다 — iOS가 Safari를 강제로 포그라운드에 띄워 방해가 크다.

이 방식은 **홈 화면 아이콘과 걸음 연동을 하나로 해결한다.**

구현 요구사항:
- `steps`는 `Number()` 변환 후 범위 검증 (0–100000), `date`는 `YYYY-MM-DD` 형식 검증
- 같은 날짜는 **누적이 아니라 덮어쓰기**
- 읽은 뒤 `history.replaceState()`로 쿼리 파라미터를 URL에서 제거
  (새로고침 시 오래된 값이 다시 적용되는 것 방지)
- 단축어 설정 안내를 설정 화면에 단계별로 넣는다

### 폴백: 자동 적립

단축어를 안 쓰는 경우 평일에는 "출퇴근 걷기 45분"을 기본으로 깔아둔다.
실데이터는 아니지만 마찰이 0이고 "이미 해낸 것으로 연다"는 목적은 달성된다.
단축어가 실제 값을 주면 그걸로 덮어쓴다.

### 검증 필요

실제 동작은 **구현 후 아이폰에서 직접 테스트해야 확인된다.**
단축어 동작을 개발 환경에서 재현할 수 없다.

## 12. 기록 탭 (그래프)

라이브러리 없이 **인라인 SVG로 직접 그린다.** 390px 폭에서 읽혀야 한다.

- **메인**: 세션별 `painFreeKm` 선 그래프 (6장 파생값). 선이 올라가는 것이 회복의 증거.
  통증이 있었던 세션은 점을 다른 색으로 찍어 구분한다
- **보조**: 일별 걸음 수 막대 (작게)
- 아래에 세션 목록 (날짜, 종류, 거리, 통증)

두 지표를 한 차트에 이중 축으로 겹치지 않는다 — 폰 폭에서 읽을 수 없다.

## 13. 파일 구성

빌드 도구 없음. 전부 평범한 `<link>` / `<script src>`.

```
index.html              마크업 + 부트스트랩
styles.css              손으로 쓴 CSS
app.js                  로직
data.js                 운동 정의 / 자투리 미션 풀 / 사다리
manifest.webmanifest
sw.js
icons/icon-180.png      (apple-touch-icon)
icons/icon-192.png
icons/icon-512.png
```

`data.js`를 분리하는 이유: 운동이나 미션을 추가할 때 로직을 건드리지 않아도 된다.

기존 `index_old01.html`, `index_old02.html`은 삭제한다 (git 히스토리에 남아 있다).

## 14. 스타일

- Tailwind CDN 제거. 손으로 쓴 CSS 약 400–600줄
- 색·간격·반경은 `:root` CSS 변수로
- `prefers-color-scheme: dark` 지원 — 밤 10시에 폰으로 보는 앱이다
- 모바일 우선. 기준 폭 390px, 좌우 여백 16px, 가로 스크롤 없음
- 터치 타깃 최소 44px

## 15. PWA

- `manifest.webmanifest` — name, short_name, `start_url: "/"`,
  `display: "standalone"`, theme_color, background_color, icons
- `<link rel="apple-touch-icon" href="icons/icon-180.png">`
  — **iOS는 manifest의 icons를 무시하고 이것을 쓴다**
- `<meta name="apple-mobile-web-app-capable" content="yes">` — 전체화면 실행
- `<meta name="theme-color">`
- `sw.js` — app shell을 cache-first로. Tailwind를 걷어내므로 외부 의존성이 없어
  오프라인이 완전히 동작한다 (지하철 터널 대응)
- 서비스워커 버전 상수를 두고 배포 시 갱신 → 오래된 캐시가 남지 않게
- **iOS 설치 안내**: `display-mode: standalone`이 아니고 iOS Safari면
  "공유 → 홈 화면에 추가" 안내를 한 번 표시. dismiss 여부를 localStorage에 기억.
  iOS는 설치를 먼저 권하지 않는다

## 16. 범위 밖

- **식단 추천** — ITBS에서 부하 관리·엉덩이 근력에 비해 약한 레버다.
  방치되는 탭을 하나 더 만드는 셈이 된다. v2에서 재검토
- **푸시 알림** — 두 달 써보고 필요성이 확인되면
- **8주 플랜 탭** — 상태 기반 진행으로 대체
- **기존 v2 데이터 마이그레이션** — 인덱스 기반이라 복원 불가능
- **기기 간 동기화 / 계정** — localStorage, 폰 단일 기기 기준
